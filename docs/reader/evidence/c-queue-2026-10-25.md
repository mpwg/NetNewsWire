All eight cancelled waiters remain suspended until the blocked owner is released, including calls cancelled before acquisition. Their cancellation result eventually arrives, but only after unrelated work completes. The old queue used nonthrowing continuations without cancellation handling.

Each queued operation now has its own UUID and checked throwing continuation. Acquisition checks cancellation before taking a slot and again when installing a waiter. A cancellation handler schedules removal on the owning FreshRSSClient actor, removes only that UUID and resumes it with CancellationError. Cancellation does not release another operation's busy slot. Successful handoff stays FIFO; a cancellation racing with handoff is handled by the existing post-acquisition check and defer release. All four acquisition entry points propagate failure.

An internal read-only queuedOperationCount diagnostic lets the tests wait for the actual suspended state. Bounded polling observes that state; it does not assume task ordering from a fixed delay. Controlled transport response counts and real ReaderStore queries provide separate outcome evidence.

The first implementation attempt without an explicit continuation type fails compilation with the Swift diagnostic Failed to produce diagnostic for expression. Adding CheckedContinuation<Void, any Error> resolves inference without disabling compiler checks. That failed build is not counted as a test execution.
