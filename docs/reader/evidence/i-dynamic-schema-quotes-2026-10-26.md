# I: native dynamic-schema quotation diagnostic

Status: **synthetic Mac diagnostic; offer quality and full product acceptance remain open**. The v12 source-literal candidate remains rejected and is not integrated on main. This diagnostic is retained separately on `codex/reader-schema-diagnostic`; its actual-model tests intentionally expose an observed failure and are not added to the shipping test plan.

The previous v12 public evaluation included a Foundation Models JSON-generation error while emitting a source literal with embedded double quotes. To distinguish schema size and response limit from the literal spelling, the same nested dynamic schema and synthetic offer are exercised with five or185 allowed string choices, greedy sampling, and either no explicit output-token limit or1200 tokens. Four cases use a condition containing embedded double quotes; four otherwise use an unquoted condition. The on-device model is available and PCC is not used.

| Synthetic condition | Choices | Output limit | Observed result |
|---|---:|---|---|
| Embedded double quotes | 5 | None /1200 | Both fail: native response cannot be completed into valid JSON; the emitted condition contains unescaped inner quotes. |
| Embedded double quotes | 185 | None /1200 | Both fail with the same invalid JSON form. |
| No embedded double quotes | 5 | None /1200 | Both return decodable required fields and the expected synthetic product, merchant, price and conditions. |
| No embedded double quotes | 185 | None /1200 | Both return decodable required fields and the expected synthetic product, merchant, price and conditions. |

The explicitly counted input is350 tokens for five quoted choices and6100 for185; unquoted controls count338 and6088. All are below the local8192-token context, though this count of serialized schema plus input does not prove the framework's exact internal prompt accounting. The no-limit control shows the failure is reproducible without a1200-token cap in this specific example; it does not prove general immunity to response truncation. Apple's [GenerationOptions documentation](https://developer.apple.com/documentation/foundationmodels/generationoptions) separately warns that strict output limits can yield malformed responses.

This is an isolated reproduction on macOS27.0.1 / build26A434 and the available local model, not proof of a universal framework defect across OS versions, models, schemas or punctuation. The synthetic choice `pickup only` is lower-case while the input sentence starts with `Pickup only`; the setup investigates response encoding/shape and does not test verbatim source validation or semantic quality. The successful controls do not accept the source-literal offer generator or the earlier real corpus. A production workaround must retain exact source ownership and explicitly recheck roles, exclusions, negations, price mapping and all-original links. Do not silently strip, rewrite, or omit publisher quotes or retry public samples for a preferred outcome.
