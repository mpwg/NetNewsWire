# Repository guidance

- Keep source code, comments, test names, commit messages, GitHub work-package descriptions, and canonical documentation in English. German belongs in localization resources and explicitly identified translation fixtures.
- Use Xcode MCP for interactive Xcode operations, including project and target creation, build settings, entitlements, builds, and native test execution. Keep projects and schemes close to Apple's templates. Do not generate Xcode projects, schemes, or test plans with Python or other scripts.
- Preserve the existing Reader implementation and its Swift packages during project migration. Do not rebuild the product from scratch.
- Use Swift Testing for every code-testable app and runner contract: domain, persistence, synchronization, content, intelligence, validation and presentation state. Use native XCTest/XCUIAutomation only for behavior that requires the actual platform UI, including windows, sheets, focus, input and rendering. Do not duplicate code-testable logic in UI tests.
- Do not use OCR for Reader verification. The owner chose text-only checks on 2026-10-26: inspect saved/extracted text directly in the actual WebKit document. Do not reintroduce image-export or pixel-analysis work for these code contracts.
- Prefer pure unit tests for business rules and small Swift Testing integrations for service/store contracts. Actual WebKit documents and directly hosted SwiftUI component lifetimes can also use Swift Testing; using a native framework alone is not a reason to add XCUIAutomation. Reserve app UI automation for behavior that cannot be proved at these smaller boundaries.
- Article HTML is untrusted data. Download only the main HTML document through bounded transport; never navigate WebKit to its website or attach source DOM to a live document. Keep source scripts, event handlers, publisher CSS, all article images (including data/SVG), media, forms, frames and other subresources blocked. Native WebKit content rules, disabled content JavaScript, strict CSP and passive DOM copying are separate boundaries. Only bundled Readability and Reader-owned parser code may run in the isolated client world. External HTTP(S) links require an explicit link action; disable previews. Prove restrictions with native Swift Testing controls, including actual HTTP request counts. Do not claim absolute immunity to engine defects or infer final-platform acceptance from Mac results.
- Use English `lowerCamelCase` function names without spaces, including test functions. Use `@Test("Readable description")` for Swift Testing display names.
- Enable Approachable Concurrency and treat compiler warnings as errors in every Reader app, test, and ReaderKit target, in Debug and Release. Keep library isolation explicit where needed; do not disable these settings to bypass failures.
- The first macOS window must open on launch without Command-N. Do not hide a failed launch by creating a window in test setup. Use stable window identities and accessibility identifiers.
- A repeated OPML import without folder information preserves the existing category, as explicitly chosen by the owner. It is not an implicit unfile command. Export follows confirmed current server membership and reuses imported hierarchy only for its matching category.
- A new subscription becomes locally visible only after its complete initial refresh succeeds, as explicitly chosen by the owner. An already confirmed FreshRSS quick-add does not authorize publishing a partial local feed/import snapshot. Propagate refresh failures; do not claim the remote subscription was rolled back. Existing confirmed feeds may merge OPML metadata locally without HTTP.
- Treat external FreshRSS, PCC entitlement, physical-device, accessibility, and performance acceptance as separate evidence. Never replace these with a successful build or a mocked contract test.
- On 2026-10-25 the owner explicitly authorized deleting the original NetNewsWire and superseded Reader paths now, relying on Git history. This supersedes the earlier retirement-after-acceptance restriction. Keep only the active `Reader/Reader.xcodeproj`, ReaderKit, current tooling and evidence; do not keep archive copies or compatibility projects in the repository. Product/platform acceptance remains independent of source retirement.
- Preserve unrelated changes in the active Reader. Never commit credentials or personal account data. Retain the root MIT notice and Mozilla Readability license and pinned-source attribution. The superseded JSDOMParser resource was retired after hosted acceptance of its native replacement; Git history retains it.

- On 2026-10-26 the owner chose authoritative FreshRSS unread membership for retained stars after unsubscription: an ID absent from a complete successful unread snapshot is read, except while an unacknowledged local read-status revision takes precedence. This supersedes the original orphan read-status-preservation requirement in #40. Star retention itself is unchanged; never infer a read transition from a failed or incomplete status fetch.
- On 2026-10-26 the owner chose multiple stages for long-text inference under #54: extract source-bound facts from bounded sections, then consolidate those facts into a shared digest. Preserve source provenance and the existing validation/read-status contracts.

- On 2026-10-26 the owner chose key-statement selection for digests: summaries may omit less important details, but every original article must remain linked. Preserve conditions and negations of selected claims and their supporting provenance. Do not require every fragment or independent fact to appear, and do not treat links to all originals as proof of semantic correctness.
