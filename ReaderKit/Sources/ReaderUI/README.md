# ReaderUI

Normal feed rows load thumbnails through the shared FeedImageService actor. Each icon reads its nearest display scale and a Dynamic Type scaled size, cancels its view task when its request changes, and checks cancellation before replacing the displayed image. ImageIO decoding stays outside MainActor. Missing or invalid images use a system-symbol fallback; digest feeds keep their Sparkles mode symbol. This wiring does not by itself establish native responsiveness or energy acceptance under image load.

The native Mac image-load scenario now verifies scrolling and account-form interaction while the shipping pipeline handles large synthetic homepages, HTTP 503 fallbacks and 4096-pixel images. Shared SwiftUI views for macOS, iOS and iPadOS 27 and later. Every ReaderWindow owns a ReaderSession with its own selection, search, presentations and query generation. ReaderServices shares only persistence, FreshRSS and content/intelligence services.

The view's query task uses the typed Hashable/Sendable ReaderQueryIdentity, keeping optional sidebar selection and search separate. The initial all-article state and the first Unread selection cannot share a task key, and separator characters cannot create collisions. Selected-article lookups have a separate generation and cancellation guard, including A→B→A transitions and older errors. [Current D evidence](../../../docs/reader/evidence/d-2026-10-25.md) records seven reproduced failures and their repair; final shared-platform acceptance remains separate from the current Mac checks.

Query errors use the same current generation, matching query identity and cancellation guards as successful results. An ordinary error from already-running work cannot revive a cancelled query or replace a changed search's state; a still-current error remains visible. Exact off-page source selection survives refresh and shows fresh extracted text without expanding the loaded page, then clears when the published filter/search changes. Real-store code journeys cover ordered ordinary rows, read/unread/star/unstar actions, normalized search, selection reconciliation and digest badges/counters. Visible entries can include a digest while loaded-original counts include only its unbundled rows. [State evidence](../../../docs/reader/evidence/d-state-2026-10-25.md) preserves the two reproduced error failures and current verification scope.

Articles and daily digests remain accessible together. Search, stars and feed navigation expose originals; incomplete or failed summaries never hide unprocessed articles. Opening content changes no read status. Marking a digest read uses exactly the sources of its displayed revision.

On Mac, the timeline uses Apple's native multiple-selection List. Shift/Command selection supports shared read/unread and star/unstar actions in the selection toolbar and item-based context menu. Multiple entries show an aggregate detail view instead of an arbitrary article. Commands capture their exact account-scoped keys before asynchronous work. Digest selections retain their selected source revisions across refreshes; overlapping sources are deduplicated, and mixed digest selections disable star actions. A newly published filter clears the previous selection; refreshes retain only visible selected rows. An explicitly opened source outside the loaded page stays accessible.

Selection preparation uses cached snapshots and performs no repository lookup. The feed-wide read action is available from cached feed/row identity in sidebar and timeline context menus. It presents a native item-based confirmation before requesting unread keys. Only confirmation calls ReaderRepository.markFeedRead; ReaderStore selects current unread keys and commits statuses/outbox revisions in one actor-owned transaction. This includes articles arriving while the menu was open and leaves arrivals after the commit untouched. A removed feed fails without changing retained originals; cancellation before the write makes no changes. Empty or already-read feeds add no status revisions. The session prevents duplicate in-flight commands for the same feed and flushes only its affected account after persistence.

The list queries pages of up to 200 articles. Covered originals are filtered while gathering rows; further raw pages load until enough visible articles are available or the store is exhausted. A large deal feed therefore cannot displace ordinary feeds from the first visible page. Selected articles and sources load by account-scoped identity. The footer distinguishes visible entries from loaded originals. Store revision streams invalidate other windows. UI state belongs to MainActor; services own I/O.

Scene activation refreshes FreshRSS. Simultaneous windows register separate waiters on the same account-owned job; automatic refresh does not repeat within 60 seconds of success. Manual refresh starts a new job after completion and joins one already running. Cancelling a window promptly releases its waiter with CancellationError and keeps accepted account work running, including when all current windows leave. A later caller can join that job. Failure clears ownership without recording a successful debounce; the next automatic call retries. [Controlled code evidence](../../../docs/reader/evidence/e-refresh-2026-10-25.md) covers actual overlap, caller completion and service lifetime. iPhone navigation initially shows the sidebar, making account setup directly accessible.

The app uses the native Apple-template project at `Reader/Reader.xcodeproj`; do not run the superseded generator. ReaderSessionTests and other state contracts use Swift Testing with isolated stores. ReaderSmokeTests remains native XCTest/XCUIAutomation. The first Mac window must open automatically without Command-N. The second-window test keeps both sheets open and checks independent drafts/cancellation. Window cycling uses the native keyboard command so overlapping windows on small displays do not turn clicks into interactions with the wrong window.

English is the source language. Text and control resources explicitly use this module's bundle; German translations and plural forms live in its String Catalog. Domain/formatting checks primarily run as code tests, including compiled English/German resources.
