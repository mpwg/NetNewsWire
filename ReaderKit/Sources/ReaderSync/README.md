# ReaderSync

FreshRSS-only Google-Reader-API client and device-local Keychain credentials. No legacy Account, parser, FMDB, CloudKit, or private service keys are linked.

`FreshRSSClient(repository:credentials:session:)` owns `refresh(account:)`, `flush(account:)`, and confirmed feed/folder mutations. `KeychainCredentialStore(service:)` stores API passwords under an app-specific service (use the Debug bundle identifier for Debug).

All credential operations check task cancellation before entering Security.framework, including each add/update recovery call after a concurrent-item race. A synchronous OS call already in progress completes. Transient OS failures are surfaced immediately, with no blocking retry loop. An internal synchronous adapter permits isolated error-path verification; the public initializer uses the system implementation. Code contracts cover all three operations, three error statuses, pre-cancellation, cancellation between recovery calls, device-local protection and MainActor progress while an OS call is blocked. They use fake OS responses and never address app account credentials.

Every operation is serialized per account across its network suspension points. Refresh applies one authoritative snapshot only after every page and content batch succeeds. It never uses a publication-time `ot` cutoff. Pending read/star changes are sent before refresh and acknowledged using the exact outbox UUIDs; the repository protects newer pending state. Missing requested content, malformed JSON, non-success HTTP, and failed mutations propagate errors. API auth and write tokens renew once on authorization rejection, without logging passwords or tokens.

Code contracts verify that a cancelled refresh sends no authentication request and that cancellation during the first 500-item status batch prevents the next batch while retaining all exact pending revisions. Missing article titles use the package's English source string and compiled German translation; a parameterized resource test verifies both languages explicitly.

The installation root or explicit `/api/greader.php` URL is accepted. Credentials are the FreshRSS username and separate API password, not browser/SSO credentials. HTTP is accepted for explicitly configured self-hosted installations; HTTPS is recommended. The client downloads complete ID lists and article contents in batches of 500; no silent page limit is applied. Live FreshRSS integration remains a separate acceptance criterion.

`IconService.icon(for:)` keeps homepage jobs independent and coalesces consumers of the same URL. It bounds active jobs (three by default), streams at most 1 MiB per image / 512 KiB per HTML response, accepts image MIME types, and caches at most 32 successful results for one day. A failed homepage still tries its origin's `/favicon.ico`; transient or missing icons are not permanently cached. Cancellation of the last consumer cancels the shared request and prevents further candidates.

Each download now owns a native URLSessionDataTask with a task-specific delegate. It validates headers and bounds received chunks even without Content-Length, then settles on task completion and releases its task/continuation references. The delegate is assigned once before resume. This avoids the retained-session result observed after early AsyncBytes termination on the exercised Mac runtime. The supplied session remains caller-owned; IconService cancels only its own task. Full service-graph and completed/cancelled image-job tests require the actors, observers and invalidated fixture transport to release. See [current lifetime evidence](../../../docs/reader/evidence/g-lifetimes-2026-10-25.md).

Metadata extraction tokenizes the bounded HTML on the service actor, stopping at explicit head closure or the start of body content, including an implicit body. It respects quoted tag delimiters and skips comments, raw-text elements and nested template content. This is a metadata selector, with no document rendering or JavaScript execution. Nine parameter cases cover these boundaries. The head/raw-text distinctions are based on the [HTML parsing rules](https://html.spec.whatwg.org/multipage/parsing.html#parsing-main-inhead). A controlled request gate holds A's icon response while B completes, proving independent results and retry without relying on task timing.

`FeedImageService.image(for:maximumPixelSize:)` uses those bounded bytes and ImageIO to decode thumbnails on its own actor. Callers supply the required pixels from their local display context. Dimensions are clamped to 1–256 pixels; at most 32 decoded thumbnails are cached for one day. Pending callers recheck the decoded cache after awaiting shared bytes. Malformed image data evicts the encoded cache entry so a later call can retry. ReaderServices shares this service across windows; normal feed rows display its thumbnails, while digest feeds retain their mode symbol. Real PNG tests cover aspect ratio, scale variants, fragment normalization, cache reuse, invalid-data retry and excessive/invalid size requests. Native Mac image-load interaction is evidenced; final platform, energy and real Keychain/FreshRSS acceptance retain their explicit limits in the matrix.

`OPMLImportService(repository:client:).importDocument(_:account:)` validates the entire OPML document before writes, coalesces identical subscriptions and rejects the same URL under conflicting category paths. FreshRSS receives the full joined folder path (`A/News`, `B/News`) as a flat category name. The original path and optional homepage are retained locally in `FeedPreferences`, using the repository's atomic import-metadata merge so concurrent edits to digest mode, cloud permission or timezone cannot be overwritten. `FreshRSSClient.addSubscription(...)` returns the confirmed `FeedKey` from the API, so redirects cannot misassign metadata. The original imported URL is retained for idempotent repeated imports even when FreshRSS canonicalizes that URL. Server mutations cannot be rolled back as one document-wide transaction; on failure the error is propagated and a repeated import reuses already confirmed subscriptions.
