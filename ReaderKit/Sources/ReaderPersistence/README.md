# ReaderPersistence

ReaderStore is the local SwiftData implementation of ReaderRepository for OS 27 and later. An actor owns the ModelContext created inside that actor; only Sendable snapshots leave the store. CloudKit is disabled. Debug and Release supply different store URLs. Tests use isolated in-memory or temporary file stores. Legacy NetNewsWire databases are never opened or migrated.

Imported OPML homepages are device-local feed preferences and fill missing server metadata; FreshRSS homepages take precedence. The original imported folder path is retained locally. `mergeImportMetadata(feed:homePageURL:folderPath:feedURL:)` reads and writes these values in one actor transaction, preserving current mode, cloud consent and time zone. Known imported URLs are retained; a nonempty new folder path is accepted, while an empty path cannot erase known hierarchy.

`applyRefresh` requires a complete successful fetch of every required FreshRSS status/subscription page. Feeds, folders and status lists are authoritative; article payloads are incremental. Missing articles in a payload do not imply deletion. For duplicate identities, the last complete version in response order wins, while original arrival time stays stable. Pending local status changes take precedence over remote answers.

Status and outbox changes commit together. Acknowledgements remove only the exact sent UUID revision. Errors roll back the operation. Unsubscribing removes only unstarred articles without pending writes or digest references; protected originals remain accessible. Automatic age-based cleanup is not implemented.

For retained stars after unsubscription, the owner chose authoritative complete FreshRSS unread membership: an absent ID becomes read unless a pending local read-status revision overrides it. Server refresh does not invent an outbox change. `markFeedRead(_:)` is an explicit asynchronous capability called after confirmation. It verifies the subscribed feed and selects its currently unread account-scoped keys in the same transaction that writes read status and outbox revisions. It has no timeline-page limit and does not modify already-read entries or their pending UUIDs. Feed/account boundaries, empty/repeated commands, removed feeds, pre-operation cancellation and arrivals before confirmation/after commit are covered by four additional Swift Testing functions / six cases. Repository implementations without this atomic capability fail explicitly instead of using a paged snapshot fallback.

`updateContent` caches locally extracted full text. An unchanged refresh retains that cache; changed feed content or original URL invalidates it. Production extraction passes the original ArticleSnapshot for atomic comparison, rejecting late results after changes to title, content, feed or URL. `saveDigest(_:expectedSources:)` verifies every source version and the complete current source set for that arrival day. Read-status changes alone do not invalidate content work. Stale work returns false without a successful write event.

Search normalizes title/text and filters in the store, with at most 1,000 results per page. It is substring search without relevance ranking, ordered by descending arrival and stable identity. Folder queries require an account ID and consider only that account's feed memberships. Empty folders return no articles. `article(_:)` loads an exact account-scoped identity outside the visible page.

`ReaderRepository.unreadCounts()` returns complete account-bound feed totals, independent of timeline paging/search. ReaderStore requests only account/feed identifiers and enumerates unread rows in batches of 500, with cooperative cancellation and no writes/outbox events. `currentRevision()` exposes the actor's committed-write version. ReaderSession accepts metadata, timeline and counts only when the version remains unchanged across the read; a mixed result or obsolete error preserves the prior coherent state. Its existing change observer consumes the next committed revision. Cached `ReaderUnreadCounts` values deduplicate folder memberships, keep accounts separate and include retained orphan originals in account/library totals. Native sidebar badges use these complete totals rather than the loaded page.
