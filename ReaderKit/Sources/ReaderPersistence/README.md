# ReaderPersistence

ReaderStore is the local SwiftData implementation of ReaderRepository for OS 27 and later. An actor owns the ModelContext created inside that actor; only Sendable snapshots leave the store. CloudKit is disabled. Debug and Release supply different store URLs. Tests use isolated in-memory or temporary file stores. Legacy NetNewsWire databases are never opened or migrated.

Imported OPML homepages are device-local feed preferences and fill missing server metadata; FreshRSS homepages take precedence. The original imported folder path is retained locally. `mergeImportMetadata(feed:homePageURL:folderPath:feedURL:)` reads and writes these values in one actor transaction, preserving current mode, cloud consent and time zone. Known imported URLs are retained; a nonempty new folder path is accepted, while an empty path cannot erase known hierarchy.

`applyRefresh` requires a complete successful fetch of every required FreshRSS status/subscription page. Feeds, folders and status lists are authoritative; article payloads are incremental. Missing articles in a payload do not imply deletion. For duplicate identities, the last complete version in response order wins, while original arrival time stays stable. Pending local status changes take precedence over remote answers.

Status and outbox changes commit together. Acknowledgements remove only the exact sent UUID revision. Errors roll back the operation. Unsubscribing removes only unstarred articles without pending writes or digest references; protected originals remain accessible. Automatic age-based cleanup is not implemented.

`markFeedRead(_:)` is an explicit asynchronous capability called after confirmation. It verifies the subscribed feed and selects its currently unread account-scoped keys in the same transaction that writes read status and outbox revisions. It has no timeline-page limit and does not modify already-read entries or their pending UUIDs. Feed/account boundaries, empty/repeated commands, removed feeds, pre-operation cancellation and arrivals before confirmation/after commit are covered by four additional Swift Testing functions / six cases. Repository implementations without this atomic capability fail explicitly instead of using a paged snapshot fallback.

`updateContent` caches locally extracted full text. An unchanged refresh retains that cache; changed feed content or original URL invalidates it. Production extraction passes the original ArticleSnapshot for atomic comparison, rejecting late results after changes to title, content, feed or URL. `saveDigest(_:expectedSources:)` verifies every source version and the complete current source set for that arrival day. Read-status changes alone do not invalidate content work. Stale work returns false without a successful write event.

Search normalizes title/text and filters in the store, with at most 1,000 results per page. It is substring search without relevance ranking, ordered by descending arrival and stable identity. Folder queries require an account ID and consider only that account's feed memberships. Empty folders return no articles. `article(_:)` loads an exact account-scoped identity outside the visible page.

The presentation follow-up compiles four additional Swift Testing cases against the actual ReaderSession reload path, checking warmed full-text caches, complete timeline/detail snapshots and search after canonical refresh. Runtime confirmation of that consumer matrix is still pending; store-only success is not its acceptance.

`changes()` provides a buffered revision stream with an initial value and a new revision after committed writes. Multiple windows observe the same commits. Ending observation does not retain the store in a cycle. Failed operations publish no success revision.

The persistence contracts run in the native unhosted ReaderTests target through Xcode MCP. They cover exact acknowledgements, pending status, canonical versions, deletion-only counts, folders, retention, rollback, search and reopening a durable store. The canonical-version contract now covers new/existing articles and both response orders: four isolated cases compare the entire snapshot, exact lookup, winning/discarded/old search terms, starred queries, committed revisions and a foreign account with the same remote ID, including repeated refreshes. All four pass locally on the exercised Mac; [current evidence and open consumer scope](../../../docs/reader/evidence/b-canonical-identity-2026-10-26.md) distinguish that proof from hosted and presentation acceptance. The separate ReaderStoreRecoveryProbe exercises the shipping core across three processes: write 10,000 synthetic articles, SIGKILL the seed process after its commit marker, recover in a fresh process and reopen after deletion in a third. It checks exact pending UUIDs, rollback, canonical content, stars, digest sources and local preferences.

The probe uses a new temporary directory and no personal credentials or accounts. Its CI orchestrator writes report/log artifacts and accepts only a new `--results-dir`. It is not an app dependency. [B evidence](../../../docs/reader/evidence/b-2026-10-24.md) records results and limits. Complete app UI restart and real FreshRSS/device integration remain separate acceptance work.

The current probe also retains a separate subscription and an independent star without pending writes or digest protection. Its final process emits actual retained IDs, stars, subscription IDs and status fields; report counts derive from that payload. The local three-process run passes with three protected originals and two pending revisions. Two expanded zero/nonzero-subscription store cases and two actual ReaderSession Starred/selection/detail cases compile and await execution. Retained unread-state policy, visible Starred presentation, complete app restart and fresh hosted proof remain open.
